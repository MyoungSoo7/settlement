# 서울 IT 사업장 국민연금 데이터 Flyway 설계

## 목표

2026년 7월 23일 배포된 국민연금 사업장 공개데이터 중 자료생성월이 `2026-06`인 서울 소재 소프트웨어·IT 서비스 사업장을 선별해 `company-service`에 재현 가능하게 적재한다. 원본 CSV는 Git에 올리지 않고, 검증된 SQL과 생성기만 추적한다.

## 확정 범위

- 배포일: `2026-07-23`
- 자료생성월 및 DB `snapshot_month`: `2026-06`
- 지역: 도로명 주소를 우선하고 지번 주소를 보조로 사용했을 때 `서울특별시`로 판정되는 활성 사업장
- 업종: 아래 12개 소프트웨어·IT 서비스 업종코드
  - `722000` 응용 소프트웨어 개발 및 공급업
  - `724000` 데이터베이스 및 온라인 정보 제공업
  - `721000` 컴퓨터 시스템 통합 자문 및 구축 서비스업
  - `722004` 시스템 소프트웨어 개발 및 공급업
  - `642004` 포털 및 기타 인터넷 정보 매개 서비스업
  - `722005` 컴퓨터 프로그래밍 서비스업
  - `729000` 기타 정보 기술 및 컴퓨터 운영 관련 서비스업
  - `722002` 모바일 게임 소프트웨어 개발 및 공급업
  - `722003` 기타 게임 소프트웨어 개발 및 공급업
  - `722001` 유선 온라인 게임 소프트웨어 개발 및 공급업
  - `723001` 호스팅 및 관련 서비스업
  - `940926` 소프트웨어 프리랜서
- 원본 기준 후보 수: 11,318건. 실제 수용 건수는 기존 도메인 검증과 6자리 사업자번호 앞자리 요건을 적용한 결과를 메타데이터에 기록한다.
- 제외: 컴퓨터 제조·도소매·수리·임대·학원·게임방처럼 소프트웨어·IT 서비스 제공 자체가 주업종이 아닌 사업장

## 데이터 흐름

1. 로컬에서 ignored CSV를 CP949로 읽는다.
2. 배포본의 모든 행이 `자료생성년월=2026-06`인지 검증한다. 다른 월이 하나라도 있으면 생성을 중단한다.
3. 활성 상태, 서울 주소, 허용 업종코드, 필수 문자열, 수치 필드, 6자리 사업자번호 앞자리 조건으로 필터링한다.
4. 복합키 `(workplace_name, biz_reg_no_prefix, snapshot_month)` 중복이 없음을 검증한다.
5. 원본 SHA-256, 원본 행 수, 후보 행 수, 수용 행 수를 계산한다.
6. 신규 버전 Flyway SQL을 생성한다. 이미 존재하는 출력 파일은 덮어쓰지 않고 실패한다.
7. Flyway는 기존 `V20260804090000`을 수정하지 않고 전진 보정한다.

## Flyway 설계

신규 마이그레이션은 다음을 하나의 PostgreSQL 트랜잭션에서 수행한다.

1. `workforce_aggregate_build`에 다음 출처·범위 메타데이터를 추가한다.
   - `source_release_date`
   - `source_sha256`
   - `coverage_scope`
   - `region_scope`
   - `industry_scope`
2. `snapshot_month=2026-06`의 기존 표본 원천행과 파생 집계를 제거한다.
3. 서울 IT 전체 범위의 검증된 INSERT 행을 적재한다.
4. 2026년 보험료율 `0.095`를 사용해 집단 중앙값과 사업장 백분위를 재생성한다.
5. 집계 메타데이터를 `COMPLETE`, `SEOUL_IT_FULL`, `SEOUL`, `SOFTWARE_IT_SERVICE`로 기록한다.

이 마이그레이션은 해당 월을 서울 IT 전용 데이터셋으로 정의하므로 같은 월의 전국 데이터와 혼합하지 않는다. 운영 환경에 별도로 적재된 동일 월 데이터가 있으면 조용히 덮어쓰지 않고 명시적인 사전조건 위반으로 실패시켜 운영자가 데이터 범위를 확인하게 한다.

## 보험료율과 금액 안전성

- 2026년 국민연금 보험료율은 사용자와 근로자 합산 `9.5%`를 적용한다.
- 보험료율은 기준월로 결정하는 도메인 정본을 두고 Java와 SQL이 동일한 기간 규칙을 사용한다.
- Java 금액 계산은 `BigDecimal`, 문자열 상수, `RoundingMode.HALF_UP`을 사용한다.
- SQL 금액 계산은 `NUMERIC`만 사용한다.
- 중앙값 계산에서 `double precision` 변환을 제거하고, 정렬된 중앙 1개 또는 2개의 `NUMERIC` 값을 평균내는 방식으로 연속 중앙값을 계산한다.
- API 금액은 기존처럼 십진 문자열로 직렬화한다.

## 조회와 사용자 안내

- 비교 조회는 `COMPLETE`이면서 `coverage_scope=SEOUL_IT_FULL`인 집계만 사용한다.
- 응답 안내문은 전국 전체 기업 통계가 아니라 `2026년 7월 23일 배포본의 서울 소프트웨어·IT 서비스 사업장`을 모집단으로 한 결과임을 명시한다.
- 국민연금 기준소득월액 상한으로 인해 고소득 구간 추정치가 실제 급여보다 낮아질 수 있다는 기존 안내는 유지한다.

## 생성기 안전장치

- 입력 CSV, 출력 SQL, 배포일, 자료생성월을 CLI 인자로 받는다.
- 개인 PC 절대경로를 제거한다.
- 출력 Flyway 파일이 이미 존재하면 중단한다.
- CP949 디코딩 오류를 조용히 치환하지 않고 실패 또는 거부 행으로 기록한다.
- 생성된 SQL 주석에 필터 버전, SHA-256, 원본·후보·수용 행 수를 기록한다.
- 원본 CSV 및 임시 산출물은 계속 Git ignore 대상으로 유지한다.

## 오류 처리와 복구

- 월 불일치, 알 수 없는 업종코드, 중복 복합키, 잘못된 수치, 기존 운영 데이터 충돌은 생성 또는 마이그레이션을 실패시킨다.
- 이미 적용된 Flyway 파일은 수정하거나 `flyway repair`로 우회하지 않는다.
- 문제 발생 시 기존 마이그레이션을 되돌리지 않고 새로운 전진 보정 마이그레이션을 작성한다.
- 원본 CSV는 운영 애플리케이션 시작이나 Flyway 실행 시 필요하지 않아야 한다.

## 테스트와 완료 조건

- 2025년 12월과 2026년 6월에는 해당 기간의 보험료율, 2026년 7월 경계에는 다음 기간 보험료율을 적용하는 테스트
- 대표 금액과 HALF_UP 경계에서 Java 추정연봉 검증
- 서울/비서울, 허용/비허용 업종, 활성/탈퇴 행 필터 테스트
- 다른 자료생성월, 중복키, 기존 출력 파일에 대한 생성 실패 테스트
- 생성 SQL에 CSV 경로·원본 내용이 포함되지 않고 SHA-256과 행 수만 기록되는지 검증
- 신규 Flyway가 기존 마이그레이션을 변경하지 않는지 checksum/diff 검증
- PostgreSQL에서 신규 Flyway 적용 후 원천행 수, 메타데이터, 집계·백분위, 9.5% 계산값 검증
- 전체 `company-service` 테스트 통과
