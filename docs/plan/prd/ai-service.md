## 1. 배경과 문제

플랫폼에는 정산·대출·투자·카드가 있고, 사용자는 "내 정산금 언제 들어와요?" 같은 질문을 한다. 그 질문에
사람이 답하면 비용이 들고, LLM 에 그냥 넘기면 **세 가지가 터진다.**

| 문제           | 구체적 손상                                                                       |
| -------------- | --------------------------------------------------------------------------------- |
| **PII 유출**   | 사용자가 주민번호·카드번호를 대화창에 붙여넣는다. 그대로 외부 LLM 으로 나간다     |
| **비용 폭주**  | 한 사용자가 반복 호출하면 토큰 비용이 선형으로 증가한다                           |
| **환각**       | 근거 없는 답을 그럴듯하게 만든다. 금융 맥락에서는 오답보다 "모른다"가 낫다        |

ai-service 는 이 셋을 **구조로** 막는다. 핵심 설계 판단은 하나다 — **못 하는 것을 못 한다고 말한다.**

## 2. 목표 / 비목표

### 2.1 목표

| # | 목표 | 성공 기준 |
|---|---|---|
| G1 | 민감정보가 외부로 나가지 않는다 | 모든 LLM 호출이 단일 마스킹 지점을 통과 |
| G2 | 비용이 사용자당 상한을 갖는다 | 분·일 이중 한도, 초과 시 429 |
| G3 | 실패를 성공으로 위장하지 않는다 | LLM 실패 시 폴백 응답 없음, 저장도 없음 |
| G4 | 답변에 근거를 붙일 수 있다(선택) | RAG 활성 시 유사도 하한을 넘는 청크만 근거로 |
| G5 | 대화 내용이 평문으로 남지 않는다 | AES-GCM 봉투 암호화 저장 |

### 2.2 비목표

| # | 비목표 | 이유 |
|---|---|---|
| N1 | 폴백 응답 생성 | "답이 나왔다"는 착각을 준다. 실패는 실패로 보여야 한다 |
| N2 | 무관한 근거라도 붙이기 | 무관한 근거는 없는 것보다 나쁘다 — 환각을 오히려 부추긴다 |
| N3 | 공급자 추상화 레이어의 일반화 | 포트 하나 + 배타 어댑터로 충분 |
| N4 | 대화 원문 보존 | 마스킹 후 저장이므로 원문은 복구되지 않는다(→ G-4) |

|---|---|

## 5. 핵심 유스케이스

### UC-1. 사용자가 민감정보를 붙여넣는다

1. 사용자가 "제 주민번호 900101-1234567 로 조회해주세요"라고 입력한다.
2. **LLM 호출 전** 단일 마스킹 지점에서 `[주민번호 마스킹됨]` 으로 치환된다.
3. 마스킹된 문장이 LLM 으로 나가고, **저장되는 것도 마스킹본**이다.
4. 카드번호는 13~19자리 후보 중 **Luhn 검증을 통과한 것만** 치환한다 — 전화번호·주문번호 오탐을 피하기 위해서다.

### UC-2. LLM 이 죽으면 사용자에게 그렇게 보인다

1. 공급자 API 가 오류를 낸다.
2. 서비스는 대체 문구를 만들지 않고 `AiUnavailableException` 을 올린다.
3. 그 교환은 **저장되지 않는다** — 실패한 대화가 이력에 남아 "답한 것처럼" 보이지 않는다.
4. 키가 아예 없을 때는 `AiNotConfiguredException` 으로 **다른 응답**이 나간다(설정 문제와 장애를 구분).

### UC-3. 근거 기반으로 답한다 (RAG, 기본 OFF)

1. `app.ai.rag.enabled=true` 일 때만 검색 서비스가 등록된다(꺼져 있으면 빈 자체가 없다).
2. 질문을 임베딩해 코사인 유사도 `min-similarity`(기본 0.55) 이상인 청크를 최대 `top-k`(기본 4) 개 뽑는다.
3. **지식베이스가 비었거나 임베딩 모델이 바뀌었으면 임베딩 호출조차 하지 않고** 무근거로 착지한다 — 유료 호출을 아낀다.
4. 유사도 하한 미만은 버린다. 근거 0건이면 근거 없이 답한다(Phase 1 과 동일 동작).

## 6. 기능 요구사항

| FR | 요구사항 | 강제 지점 |
|---|---|---|
| FR-1 | 사용자 입력은 LLM 호출 전 마스킹된다 | `ChatService` 단일 지점 |
| FR-2 | 주민번호 패턴(6+성별1~8+6)을 마스킹한다 | `PiiMasker` |
| FR-3 | 카드번호는 Luhn 통과분만 마스킹한다 | 동상 |
| FR-4 | 공급자는 정확히 하나만 등록된다 | `@ConditionalOnProperty` 배타 |
| FR-5 | 사용자별 분·일 한도를 함께 건다 | `Bucket4jRateLimiter`(버킷 1개, 대역폭 2개) |
| FR-6 | 한도 초과는 429 로 변환된다 | 예외 → 상태코드 매핑 |
| FR-7 | LLM 실패 시 폴백을 만들지 않는다 | `ChatService` |
| FR-8 | 실패한 교환은 저장하지 않는다 | 저장은 성공 경로에서만 |
| FR-9 | 대화 내용은 AES-GCM 으로 암호화 저장한다 | `ChatContentEncryptionConverter` |
| FR-10 | `CHAT_ENC_KEY` 는 정확히 32바이트여야 한다 | 아니면 기동 실패 |
| FR-11 | RAG 는 기본 꺼짐이며, 켜야 검색 빈이 등록된다 | `app.ai.rag.enabled` |
| FR-12 | 유사도 하한 미만 근거는 버린다 | `min-similarity` |

## 7. 도메인 규칙 (BR)

| BR | 규칙 | 근거 |
|---|---|---|
| BR-1 | **마스킹은 단일 초크포인트** — 우회 경로를 만들지 않는다. 규칙 추가는 한 곳에서 끝난다 | `PiiMasker.mask` 호출 지점 1개 |
| BR-2 | **Luhn 게이트** — 정밀도를 위해 재현율을 일부 포기한다. 오탐 마스킹이 사용성을 더 해친다는 판단 | `PiiMasker` |
| BR-3 | **무폴백** — 실패 시 침묵이 아니라 오류를 반환한다 | `ChatService` |
| BR-4 | **무관한 근거는 붙이지 않는다** — 근거 없는 답보다 나쁜 것이 잘못된 근거를 단 답이다 | `min-similarity` 주석 |
| BR-5 | **임베딩 모델 변경은 감지된다** — 청크마다 `embedding_model` 을 기록해 모델이 바뀌면 기존 청크를 쓰지 않는다 | `knowledge_chunks` |
| BR-6 | **3단 분리** — 마스킹 → LLM 호출 → 저장(단일 tx). 외부 호출이 트랜잭션을 잡지 않는다 | `ChatService` |

## 8. 데이터 모델

| 테이블 | 역할 | 특기 |
|---|---|---|
| `chat_conversations` | 대화 세션 | 사용자 귀속 |
| `chat_messages` | 메시지 | **내용 암호화**(`enc:v1:` 접두), 파티션드 |
| `knowledge_chunks` | RAG 청크 | `vector(768)` + `embedding_model` 기록 |
| `audit_logs` | 감사 | 파티션드 |

> **임베딩 차원이 768 인 이유**: pgvector 의 `vector` 타입은 2000 차원까지만 인덱싱된다. 3072 를 쓰려면
> `halfvec`(4000까지)로 스키마를 바꿔야 한다. MRL 학습 모델이라 절단이 허용되며, 절단 시 L2 정규화는
> 어댑터의 수동 책임이다.

## 12. 역산에서 드러난 격차

### G-1. 비용 가드가 스케일아웃에서 무력해진다

레이트리밋이 **인메모리 단일 인스턴스 전제**다(코드 주석이 명시). 인스턴스를 N개로 늘리면 사용자당
실질 한도가 N배가 된다. 교체 지점(Redis ProxyManager)은 포트 뒤라 계약은 불변이지만, **스케일아웃과
비용 가드가 상호배타**인 현재 상태가 문서화된 적은 없다.

### G-2. 마스킹 대상이 2종뿐이다

주민번호·카드번호만 마스킹한다. **계좌번호·전화번호·이메일은 그대로 LLM 으로 나간다.** 초크포인트
구조 덕분에 규칙 추가는 한 곳에서 끝나지만, 현재 커버리지가 2종이라는 사실은 "PII 마스킹이 있다"는
표현이 주는 인상보다 좁다.

### G-3. Luhn 게이트의 트레이드오프가 문서에 없다

Luhn 을 통과하는 비카드 숫자열은 **오탐 마스킹**되고, 오타가 섞인 실제 카드번호는 **통과**한다.
이 정밀도/재현율 선택이 의도된 것인지, 어느 쪽 오류가 더 비싼지에 대한 판단 근거가 남아 있지 않다.

### G-4. 감사 관점에서 원문이 없다

마스킹이 저장 이전에 일어나므로 "사용자가 실제로 무엇을 입력했는가"를 되짚을 수 없다. 분쟁·오남용
조사에서 필요할 수 있는데, 이 트레이드오프(프라이버시 우선)가 명시적 결정이었는지 확인하지 않았다.

### G-5. RAG 품질을 관측할 지표가 없다

`min-similarity` 미만이면 근거를 버리는데, **버려진 비율·근거 0건 비율**을 관측하는 경로가 없다.
지식베이스가 실질적으로 안 쓰이고 있어도(임계가 너무 높거나 문서가 부족해도) 조용히 Phase 1 처럼
동작한다.

### G-6. 임베딩 차원 절단의 정규화가 수동이다

768 차원 절단 시 L2 정규화를 **어댑터가 수동으로** 수행한다. 다른 임베딩 어댑터를 추가하면 그 책임이
전파되지 않으며, 누락 시 유사도 계산이 조용히 어긋난다.
